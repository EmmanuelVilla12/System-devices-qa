# 1.1 Análisis de la historia HU-001

**Fase:** Preparación
[Volver al flujo](../00_Flujo_metodologico.md)

## Ficha de la historia

| Elemento | Contenido |
|---|---|
| Historia | Como persona que aún no tiene cuenta, quiero registrarme con mis datos y seleccionar mi rol, para identificarme y acceder a las funciones que corresponden a mi cuenta. |
| Actor | Visitante o persona sin sesión |
| Objetivo | Crear una cuenta activa con nombre, correo, contraseña y rol, o recibir un rechazo explicado sin que se cree la cuenta. |
| Requisito / prioridad | RF-001 · Alta |
| Reglas de negocio | RN-001, RN-002 y RN-007 (la ficha no transcribe su texto; se aplican las reglas y restricciones listadas abajo) |
| Dependencias (ficha) | RNF-001, RNF-006 y HU-028 |
| Condiciones de calidad aplicables | RNF-001, RNF-004, RNF-005, RNF-006 (solo las que lista la ficha) |
| Descripción | El registro solicita nombre, correo electrónico, contraseña y rol. El nombre admite de 3 a 50 caracteres y el correo debe ser válido y no estar registrado. La contraseña debe cumplir las condiciones indicadas en el formulario. Un registro aceptado crea una cuenta activa que puede utilizarse para iniciar sesión; sus datos se muestran sin revelar la contraseña. |
| Resultado esperado | Cuenta activa registrada con los datos y el rol aceptados, o rechazo explicado sin crear una cuenta. |

## Precondiciones de la ficha

1. La persona no tiene una sesión iniciada.
2. Para completar el registro, el correo no debe estar asociado a otra cuenta.

## Flujo principal de la ficha

1. Abrir Registro.
2. Diligenciar nombre, correo electrónico y contraseña.
3. Seleccionar usuario, soporte o administrador.
4. Revisar las condiciones de contraseña que se actualizan mientras se escribe.
5. Enviar el formulario.
6. El sistema valida los datos y el límite de solicitudes.
7. Si la solicitud es válida, registrar la cuenta activa y mostrar sus datos sin contraseña.

## Reglas y restricciones

- El correo no se repite entre cuentas.
- No se exige verificación por correo ni aprobación adicional del rol.
- La cuenta aceptada queda activa; el inicio de sesión se realiza mediante HU-002.
- Una solicitud rechazada no debe crear una cuenta.

## Dependencias

| Dependencia | Tipo | Cómo se usa en este banco |
|---|---|---|
| RNF-001 | Condición de calidad | Casos ACC-REG-001 y ACC-REG-018 (contraseña no visible ni legible). |
| RNF-006 | Condición de calidad | Caso ACC-REG-016 y control de 65 s entre casos. |
| HU-028 (otro grupo) | Historia de otro grupo | Se cita como dependencia de la comunicación de errores; sus casos no se diseñan aquí. Los casos solo exigen que el error aparezca junto al campo, como dice CA-HU-001-03. |
| HU-002 (Grupo 1) | Historia relacionada (regla de la ficha) | Caso ACC-REG-017: la cuenta creada inicia sesión. |

Las historias de otros grupos se citan como dependencia o precondición; **este banco no diseña sus casos**.
