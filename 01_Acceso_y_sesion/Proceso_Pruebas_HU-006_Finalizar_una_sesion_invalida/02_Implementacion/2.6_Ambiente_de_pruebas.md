# 2.6 Ambiente de pruebas · HU-006

**Fase:** Implementación
[Volver al flujo](../00_Flujo_metodológico.md)

## Versión o recurso previsto

| Elemento | Valor previsto |
|---|---|
| Aplicación | Device Systems, instancia de ensayo separada de desarrollo y producción |
| Versión del producto | Por confirmar: se anota la versión desplegada cuando HU-006 entre a ensayo |
| Dirección de la aplicación | Por confirmar por el equipo de desarrollo (no se inventa una URL) |
| Datos | Punto de control de [2.3 Datos](2.3_Datos_de_prueba.md) |

## Características

| Característica | Aplicación a HU-006 |
|---|---|
| Instancia de ensayo separada | Instancia de Device Systems distinta de desarrollo y producción, con las funciones de gestión de sesión habilitadas. |
| Límite de 3 solicitudes por minuto | Igual configuración que en producción, pero sin afectar a las pruebas de HU-006 (no se usa este límite como criterio principal). |
| Herramientas fuera del ambiente | El banco y las incidencias se gestionan en el repositorio `System-devices-qa` y su tablero. |
| Uso exclusivo durante la corrida | Nadie más modifica estados de sesión en paralelo, porque alteraría el TTL y el resultado de las pruebas. |

## Roles y cuentas necesarias

| Rol / cuenta | Para qué se usa |
|---|---|
| Visitante sin sesión | Todos los casos de sesión caducada/rechazada (ACC-INV-001, ACC-INV-002, ACC-INV-003). |
| Cuenta base `sesion.vigente@dsqa.test` | Punto de control: sesión válida (para ACC-INV-004 y diferenciación con ACC-INV-001). |
| Cuenta base `sesion.caducada@dsqa.test` | Punto de control: sesión caducada (para ACC-INV-001). |
| Administrador del ambiente | Restaurar el punto de control y conceder lectura de la base. |
| Tester QA | Ejecutar scripts, registrar resultados, reportar incidencias. |

## Restricciones

- Los desarrolladores no tienen permisos de modificación en el ambiente de ensayo; el administrador del ambiente lo gestiona.
- Cada despliegue en ensayo tiene versión identificada (control de versiones).
- **Nunca** se usan datos reales ni el ambiente de producción.
- No se deben crear sesiones adicionales en paralelo durante la corrida; esto alteraría el TTL y los resultados de ACC-INV-001 y ACC-INV-002.

## Dependencias del ambiente

- HU-002 desplegada en la misma versión (para integración opcional en casos de sesión válida).
- HU-008 (otro grupo) define cómo se comunican los errores; si no está disponible, los casos verifican solo lo que dice CA-HU-006-03 (no se recupera acceso).
- HU-028 (otro grupo) define el manejo de sesiones caducadas; si no está disponible, los casos usan la interpretación provisional registrada en PA-01.

## Procedimientos de gestión

| Procedimiento | Cómo se aplica |
|---|---|
| Preparación de datos auditable | Respaldo del punto de control con las cuentas base `sesion.vigente@dsqa.test` y `sesion.caducada@dsqa.test`; se restaura antes de cada corrida y se anota en 3.2. |
| Accesos | Lectura de la base de ensayo (PA-05). |
| Herramientas | Navegador con panel de red, cronómetro, NVDA, emulación de dispositivo, capturas. |
| Planificación de uso | Reservar el ambiente durante la corrida. |
