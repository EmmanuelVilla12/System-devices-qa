# 4.1 Análisis y gestión de incidencias · HU-003

**Fase:** Evaluación
[Volver al flujo](../00_Flujo_metodologico.md)

> **Estado:** sin incidencias. No hay ejecución, por lo tanto no existe ningún defecto registrado. Este documento define solo el procedimiento.

## Análisis antes de reportar

Cuando un caso no obtiene el resultado esperado, el tester investiga antes de abrir la incidencia:

1. **Analizar el impacto** del defecto sobre el criterio de aceptación.
2. **Investigar las condiciones** en que se produce.
3. **Analizar la severidad** (crítica, alta, media o baja).
4. **Variar los pasos**: ejecutarlos en otro orden para ver si cambia el resultado.
5. **Variar la configuración**: otro navegador o tamaño de pantalla.
6. **Variar los datos**: por ejemplo, recargar otra pantalla protegida o con otra cuenta, para saber si el comportamiento depende de la pantalla o del rol.

## Ciclo de vida de una incidencia

```text
Nuevo → Abierto → Asignado → Corregido → (reprueba) → Verificado → Cerrado
                     │                         │
                     ├→ Rechazado (no aplica)  └→ Reabierto (persiste) → Asignado
                     └→ Diferido (bajo impacto o corrección no prioritaria)
```

| Estado | Responsable | Significado |
|---|---|---|
| Nuevo | Tester | Se identifica y registra el error durante la prueba. |
| Abierto | Desarrollo | El equipo lo recibe y empieza a analizarlo. |
| Asignado | Desarrollo | Se asigna a un desarrollador. |
| Rechazado | Desarrollo / PO | No aplica (por ejemplo, el comportamiento sí cumple el criterio). |
| Diferido | PO | Aplica, pero es de bajo impacto o su corrección no es prioritaria. |
| Corregido | Desarrollo | Se devuelve a pruebas con la versión corregida. |
| Reabierto | Tester | La reprueba muestra que no se corrigió. |
| Verificado | Tester | La reprueba es positiva. |
| Cerrado | Equipo de pruebas | Se cierra después de la verificación. |

## Severidad y prioridad para HU-003

| Severidad | Criterio | Ejemplo hipotético en HU-003 (no observado) |
|---|---|---|
| Crítica | Restaura acceso con una sesión inválida o caducada | Perfil se mostraría tras recargar con la sesión alterada. |
| Alta | Incumple un criterio | La recarga ampliaría el momento de caducidad. |
| Media | Cumplimiento parcial | Tras recargar se perdería una opción permitida del rol. |
| Baja | Presentación | Desajuste visual después de recargar. |
