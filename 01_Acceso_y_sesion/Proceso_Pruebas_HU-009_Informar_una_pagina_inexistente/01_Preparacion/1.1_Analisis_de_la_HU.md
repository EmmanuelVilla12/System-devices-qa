# 1.1 Análisis de la historia de usuario · HU-009

## 1. Información general

| Elemento | Descripción |
|---|---|
| Historia de usuario | HU-009 · Informar una página inexistente |
| Requerimiento funcional | RF-009 |
| Módulo | ACC · Acceso y sesión |
| Prioridad | Alta |
| Dependencia | HU-008 |

## 2. Historia de usuario

Como persona que navega en la aplicación, quiero recibir una explicación cuando intento abrir una dirección que no existe, para reconocer que esa página no forma parte de la aplicación y no confundirla con un problema de permisos.

## 3. Descripción funcional

Cuando una persona ingresa a una dirección que no corresponde a una pantalla existente, el sistema debe mostrar el mensaje «Página no encontrada».

La aplicación debe evitar mostrar una pantalla en blanco y diferenciar una dirección inexistente de una pantalla existente que tenga restricciones de acceso.

## 4. Actor

- Visitante sin autenticación.
- Persona autenticada.

## 5. Precondiciones

- La persona solicita una dirección de la aplicación.
- Para comprobar el caso de página inexistente, la dirección solicitada no debe corresponder a una pantalla existente.
- Para comprobar restricciones de acceso, la dirección debe corresponder a una pantalla existente protegida.

## 6. Flujo principal de página inexistente

1. La persona abre una dirección de la aplicación.
2. El sistema determina si corresponde a una pantalla existente.
3. Si la dirección no corresponde a una pantalla existente, presenta el mensaje «Página no encontrada».
4. La persona puede reconocer que la página solicitada no existe.

## 7. Flujo alternativo de acceso restringido

1. La persona abre una dirección correspondiente a una pantalla existente.
2. El sistema identifica que la pantalla tiene restricciones de acceso.
3. El sistema aplica las reglas de acceso definidas en HU-008.
4. No debe mostrar «Página no encontrada» como respuesta a una restricción de permisos.

## 8. Reglas y restricciones identificadas

- Una dirección inexistente debe producir una respuesta comprensible.
- No debe presentarse una pantalla en blanco.
- Una pantalla existente con acceso restringido no debe confundirse con una dirección inexistente.
- Consultar una dirección inexistente no debe crear ni modificar registros de usuarios, equipos o préstamos.
- No se deben agregar operaciones de negocio nuevas.

## 9. Requisitos no funcionales relacionados

- RNF-004: el mensaje debe ser identificable y comprensible.
- RNF-005: el mensaje debe ser legible en computador y dispositivos móviles, sin que el texto quede cortado.

## 10. Preguntas abiertas

| ID | Pregunta | Interpretación provisional | Casos afectados |
|---|---|---|---|
| PA-01 | ¿Cuál es el texto completo y definitivo que debe acompañar el mensaje «Página no encontrada»? | Se comprobará la presencia del mensaje indicado en la HU, sin exigir contenido adicional no especificado. | Casos de página inexistente. |
| PA-02 | ¿Qué direcciones concretas deben utilizarse para validar páginas existentes y páginas inexistentes? | Se utilizarán direcciones de prueba ficticias, previamente verificadas para el ambiente disponible. | Casos de rutas existentes e inexistentes. |

## 11. Consideraciones para el diseño de pruebas

- Se deben diferenciar visitantes y personas autenticadas.
- Se debe comprobar la diferencia entre una dirección inexistente y una pantalla existente restringida.
- Las direcciones ficticias utilizadas como datos de prueba no representan rutas confirmadas de la aplicación.
- La verificación de restricciones debe respetar la dependencia de HU-008.
- No se registrarán resultados de ejecución hasta realizar las pruebas.

## 12. Conclusión

HU-009 busca informar claramente cuando una persona solicita una página inexistente y evitar que esta situación se confunda con una restricción de acceso. El diseño de pruebas debe cubrir los criterios de aceptación y los requisitos no funcionales RNF-004 y RNF-005.
